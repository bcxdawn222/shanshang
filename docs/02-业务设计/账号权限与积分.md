# 账号权限与积分

> 文档用途：账号模型、权限矩阵、积分账本规则
> 当前状态：待验证（口径已确认，待开发）
> 最后更新时间：2026-10-30
> 对应需求：ACC-*、SET-01~03、PT-*、DVC-01~02

## 1. 账号模型

| 角色 | 创建方式 | 登录 |
|---|---|---|
| `admin` 超级管理员（V1 仅 1 个） | 部署时由环境变量初始化，不开放注册 | 账号 + 登录口令 |
| `merchant` 商家（一个账号 = 一个品牌） | 自助注册 → `PENDING` → 管理员审核 → `ACTIVE`（默认 18 格）/ `REJECTED` | 用户名 + 密码 |

- 商家状态：`PENDING / ACTIVE / REJECTED / DISABLED`。`PENDING` 登录后只看“审核中”；`DISABLED` 不能登录，服饰从设备下线。
- 密码：`scrypt` 加盐哈希；会话用 HttpOnly Cookie，改密、停用、重置密码后旧会话全部失效。
- 登录限流：同 IP + 同账号连续失败 5 次锁 15 分钟。

## 2. 权限矩阵

| 能力 | 商家 | 管理员 |
|---|---|---|
| 修改自己昵称、密码 | ✅ | ✅ |
| 修改平台名、Logo、登录背景 | ❌ | ✅ |
| 上传服饰（格位内）、填店铺位置 | ✅ | ✅（可代传） |
| 加格 | ❌ 提示“请联系管理员” | ✅ 每次 +5 |
| 服饰训练 / 上架审核 | ❌ 提示“你的账户没有权限，请联系管理员” | ✅ 提前通过 / 驳回 |
| 积分充值 | 查看联系方式和收款码 | ✅ 手动加/扣，必填备注 |
| 核销 | ✅ 仅本商家的码 | ✅ |
| 查看统计 | 仅自己 | 全部 |
| 商家审核、启停、重置密码 | ❌ | ✅ |
| 设备绑定、设备背景 | ❌ | ✅ |
| 播放列表、短剧专题、热门榜调整 | ❌ | ✅ |
| 看 Xmax 积分与换算比例 | ❌ | ✅ |

所有权限在服务端校验，前端隐藏按钮只是体验。

## 3. 积分账本

- 平台积分与 Xmax 积分分离；换算比例（平台积分 : Xmax 积分）只在总后台可配，用于成本核算，商家不可见。
- 流水类型：`ADMIN_ADD / ADMIN_DEDUCT / TRYON_CONSUME / REFUND`，只追加；`merchant.balance` 是快照，可由流水重算对账。
- 扣费：默认 1 积分/分钟，按秒累计。设备在每件服饰“离屏”（切换、结束、待机、上限到时）时上报 `{garment_id, duration_ms, session_id, seq}`，服务端按 `session_id + seq` 幂等扣到该服饰所属商家。
- 余额阈值默认 5：低于阈值时设备服饰清单不返回该商家，商家后台顶部提醒充值。
- 试穿中余额耗尽不打断，允许透支为负；单次透支上限受单次试穿上限（默认 5 分钟）约束。下次加积分先抵扣负数。

## 4. 账号使用总时长

= 本商家所有 `TRYON_CONSUME` 对应的在屏时长之和，与扣费同口径。

## 5. 设备凭证

- 设备首次启动生成设备码并显示；管理员在总后台录入设备码、名称、摆放地点完成绑定，服务端下发设备令牌。
- 未绑定或停用的设备，取服饰清单以外的所有接口（尤其临时密钥）一律拒绝。
