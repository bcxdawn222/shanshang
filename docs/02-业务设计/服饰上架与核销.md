# 服饰上架与核销

> 文档用途：格位规则、上架状态机、标签、核销码与快照流程
> 当前状态：待验证（口径已确认，待开发）
> 最后更新时间：2026-10-30
> 对应需求：GAR-*、SET-09、RDM-*

## 1. 格位

- 审核通过的商家 `slot_quota = 18`；已用 = 未删除的服饰数。
- 已用 ≥ 配额时，上传接口返回业务错误，前端“+”显示“请联系管理员”。
- 管理员加格：`slot_quota += 5`，写审计日志。删除服饰释放格位。

## 2. 标签

| 字段 | 必填 | 来源 |
|---|---|---|
| 性别 | ✅ 男 / 女 / 童 | 固定 |
| 类型 | ✅ 当季热卖套装 / 上装单品 | 固定 |
| 品类 | ✅ 单选 | 管理员维护，预置 8 个 |
| 主色 | ✅ 单选 | 管理员维护的色系列表 |
| 场景标签 | 多选 | 管理员维护：宴会、约会、闺蜜、通勤、休闲等 |
| 风格 | 多选 | 管理员维护：温柔、酷飒、高级、元气、松弛 |
| 折扣说明 | 选填 | 商家自由文字，如“凭此码 9 折” |
| 店铺位置 | 默认取商家资料，可覆盖 | 商家 |

“热播短剧同款”不是商家可选的标签，由管理员在专题里挑服饰。标签字典骨架参考 Fashionpedia（见[开源复用清单](<../03-接口与集成/开源复用清单.md>)）。

## 3. 上架状态机（审核期）

```
上传 → REVIEWING（商家端显示“训练中”+倒计时）
     → READY      ← 管理员提前通过，或 available_at 到达自动上架
     → REJECTED   ← 管理员驳回（填原因，商家可见，格位保留可重传）
READY → OFFLINE   ← 商家/管理员下架、账号停用
```

- 上传时写 `available_at = 上传时间 + 随机(50~70 分钟)`，满足“平均约 1 小时、最长不超过 2 小时”。
- 商家端文案固定：“上传服饰需要等待1-2小时的训练周期，所用时长视情况而定，最长不超过2小时。”
- 上传时服务端同步把图片转存到 Xmax 文件服务，得到公网 URL，设备直接用。

## 4. 快照与核销

```
试穿中点“扫码领优惠” → 屏幕提示“扫码将保存您的试穿照片”
→ 设备截取远端换装画面，Canvas 叠加店铺名、商品名、核销短码、折扣文字
→ 上传服务端，生成 snapshot（随机 token ≥128 bit + 6 位短码）
→ 屏幕显示二维码（指向 /s/<token>）
→ 顾客微信扫码：快照页显示固定图片，可长按保存
→ 顾客到店：店员在商家后台输入短码，或用已登录商家账号的手机扫码 → “确认核销”
```

- 短码一次性、7 天有效、只能由该服饰所属商家核销；重复、过期、跨商家一律拒绝。
- 快照页服务端直出 HTML，`noindex`，7 天后删除图片，页面显示“已过期”。
- 二维码用 node-qrcode / qr-code-styling。
- 微信内稳定打开需要备案域名 + HTTPS；域名到位前用手机浏览器验收。
