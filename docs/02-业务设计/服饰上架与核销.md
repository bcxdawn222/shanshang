# 服饰上架与核销

> 文档用途：格位规则、上架状态机、核销码与快照流程
> 当前状态：待验证（依赖 Q5、Q6、Q7）
> 最后更新时间：2026-10-30
> 对应需求：GAR-*、DEV-05~07

## 1. 格位

- 新账号 `slot_quota = 18`；已用 = 未删除的服饰数。
- 已用 ≥ 配额时，上传接口返回业务错误，前端“+”显示“请联系管理员”。
- 管理员加格：`slot_quota += 5`，写审计日志。删除服饰释放格位。

## 2. 上架状态机

```
上传 → TRAINING（训练中，倒计时）
     → READY（设备可用）     ← available_at 到达，或管理员手动通过
     → OFFLINE（下架）       ← 商家/管理员下架、账号停用
     → REJECTED（驳回）      ← 管理员驳回（需 Q6 确认是否有审核）
```

- 上传时写 `available_at = 上传时间 + 随机(50~70 分钟)`，保证“平均约 1 小时、最长不超过 2 小时”。
- 设备只拉取 `READY` 且 `available_at <= now` 的服饰。
- 技术说明：Xmax 是参考图实时换装，图片上传后即可使用，不需要真实训练。延迟是业务规则；建议利用这段时间让管理员审核图片（Q6）。
- 上传时服务端同步把图片转存到 Xmax 文件服务，得到公网 URL，设备直接用，避免设备端重复上传。

## 3. 核销码与快照

```
顾客试穿 → 设备右下角显示：店铺位置 + 二维码（指向 /s/<token>）
顾客微信扫码 → 打开快照页：试穿截图 + 商品信息 + 店铺核销码
顾客到店出示 → 店员核销 → 状态 USED，计入统计
```

- 生成时机：试穿出画面后设备截一帧（远端视频画面），上传服务端，生成 `snapshot` 记录与随机 token（不可猜测，≥128 bit）。换一件衣服生成一条新记录。
- 核销码：短码（如 8 位）便于店员输入，与 token 一一对应；一次性，核销后不可再用。
- 有效期默认 7 天（待确认）。
- 核销入口待确认（Q5），候选：
  - A. 店员登录商家后台“核销”页输入短码 / 扫快照页上的码；
  - B. 快照页上“店员核销”按钮 + 店员口令。
- 前置条件：微信内稳定打开需要备案域名 + HTTPS（Q7）。裸 IP 在微信内会被拦截或提示风险。
- 隐私：快照含顾客人像，仅凭 token 访问，页面 `noindex`，到期删除图片。

## 4. 店铺位置

服饰归属商家，商家资料里维护“店铺位置”（如“3F-A12”）；单件服饰可覆盖。
