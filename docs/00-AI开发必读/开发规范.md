# 开发规范

> 文档用途：日常修改、验证与文档维护规则
> 当前状态：已完成
> 最后更新时间：2026-10-30

## 开发流程
1. 读 PRD 对应编号和 Phase 计划，确认本次范围和验收标准。
2. 在 `feature/bcxdawn222` 开发，按 Phase 分批提 PR 到 `dev`。
3. 运行与改动相称的验证：服务端单元/接口测试、前端 `lint` + `build`、设备端在触摸屏或 CDP 下回归。纯文档改动只核对链接和内容。
4. PR 里写清测试结果、未验证事项、发布步骤和回滚方法。

## 代码规则
- 依赖版本锁定精确版本（`package-lock.json` 必须提交）。
- 密码用 `scrypt`（`node:crypto`）加盐哈希，禁止明文或可逆加密。
- 所有接口做参数校验；上传文件校验类型、大小，文件名由服务端生成。
- 分后台的所有查询必须带 `merchant_id` 条件，由服务端从登录态取，不信任前端传参。
- 积分扣减、加格位、核销写流水表，并保证幂等（业务单号唯一）。
- 设备端触摸交互统一用 `pointerup` 封装，不依赖 `click`（广告机上 click 会被吞，见交接记录）。

## 文档维护
- 需求变化先改 PRD（写修订记录），再改代码。
- 项目状态只记进展、证据、阻塞和下一步。
- 每次合入 `dev` 更新 [项目进度与待办](<../05-项目状态/项目进度与待办.md>)。
