## 系统边界

```text
              ┌──────────── 总后台（超级管理员）──┐
 apps/admin ──┤                                    ├──> apps/server ──> SQLite + 本地媒体目录
              └──────────── 分后台（商家）────────┘        │
 apps/device（广告机前台，替换双应用外壳里的“我们的试穿”）──┤──> Xmax（国内站，临时密钥）
 apps/server 直出快照页 /s/<token>（微信扫码落地）──────────┘
```

| 目录 | 技术 | 职责 |
| --- | --- | --- |
| `apps/server/` | Node 20 + Fastify + better-sqlite3 | 账号权限、商家审核、服饰与审核期、格位、积分账本、设备绑定、播放列表、快照核销、统计、Xmax 临时密钥签发、快照页直出 |
| `apps/admin/` | Vue 3 + Element Plus + Vite（基于 vue-pure-admin 精简） | 一套代码，按角色显示总后台/分后台菜单 |
| `apps/device/` | Vite + 原生 JS + `@xmaxai/sdk` | 分类导航、试穿、扫码领优惠、待机播放、星座轮盘、运势穿搭、AI智趣推荐 |
| `packages/shared/` | 纯 JS | 种子随机（cyrb53 + mulberry32）、推荐打分等前后端共用逻辑 |

## 必须保留的架构决策
1. 总后台和分后台**一套前端、一套接口**，区别只在角色权限。
2. 分后台数据隔离由服务端按登录态强制，接口层统一加 `merchant_id` 过滤。
3. Xmax 永久密钥只在服务端；设备凭设备令牌换临时密钥，未绑定设备拿不到（DVC-02）。
4. 设备拉取服饰时只返回 `READY 且 available_at <= now 且 商家余额 >= 阈值` 的数据（GAR-07、PT-03）。
5. 积分账本只追加流水，扣费按“服饰在屏时长”逐件结算（PT-02、PT-06）。
6. 埋点先写明细表，统计页查日汇总表。
7. 媒体文件（服饰图、视频、快照）存服务器本地目录，路径和对外 URL 做成配置，后续可切 OSS。

## 与现有交付物的关系
- 单机试穿页 `xmax-tryon` 是 `apps/device` 的起点，试穿链路（参考图 → `connectCamera` → `session.set` 换装）和 `bindTap` 触摸封装原样复用。
- 旧极简后端（只签发密钥）在新服务端上线（Phase 8）后下线；开发期新服务挂 `/sl/`，旧的 `/mc/` 不动。
- 广告机双应用外壳不在本仓库，Phase 8 把“我们的试穿”应用 URL 指向新的设备前台地址。
