## 系统边界

```text
              ┌──────────── 总后台（管理员）──┐
 apps/admin ──┤                                ├──> apps/server ──> SQLite + 本地媒体目录
              └──────────── 分后台（商家）────┘        │
 apps/device（广告机前台，跑在 magicmirror-dual 壳里）──┤──> Xmax（国内站，临时密钥）
 apps/h5（微信扫码快照/核销页）─────────────────────────┘
```

| 目录 | 技术 | 职责 |
| --- | --- | --- |
| `apps/server/` | Node 20 + Fastify + better-sqlite3 | 账号权限、商家、品牌、服饰、格位、积分、设备、媒体、快照核销、统计、Xmax 临时密钥签发 |
| `apps/admin/` | Vue 3 + Element Plus + Vite | 一套代码，按角色显示总后台/分后台菜单 |
| `apps/device/` | Vue 3 + Vite + `@xmaxai/sdk` | 广告机前台：分类导航、试穿、二维码角标、待机视频、玩法 |
| `apps/h5/` | Vite 原生页面 | 微信扫码打开的快照页 + 店员核销入口 |

## 必须保留的架构决策
1. 总后台和分后台**一套前端、一套接口**，区别只在角色权限（PRD A-03）。
2. 分后台数据隔离由服务端按登录态强制，接口层统一加 `merchant_id` 过滤。
3. Xmax 永久密钥只在服务端；设备凭“设备令牌”换临时密钥，未登记设备拿不到（修复旧版任何人可领 `tk-` 的问题）。
4. 设备拉取服饰时只返回 `status=已上架 且 available_at <= now` 的数据（PRD G-05）。
5. 埋点事件先写明细表，统计页查日汇总表，避免广告机长期运行后明细表拖慢报表。
6. 媒体文件（服饰图、视频、快照）存服务器本地目录，路径和对外 URL 做成配置，后续可切 OSS。
