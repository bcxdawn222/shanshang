# 闪裳设备后台系统 PRD V1.0

> 文档用途：唯一需求基线，维护需求编号、优先级与验收标准
> 当前状态：待验证（待产品评审；未决口径见[待产品确认问题](<../05-项目状态/2026-10-30-待产品确认问题.md>)）
> 最后更新时间：2026-10-30
> 依据：[原始需求-新后台功能](<原始需求-新后台功能.md>)

## 1. 产品定位

广告机（触摸屏）实时 AI 试穿设备的运营系统，三端：

| 端 | 使用者 | 作用 |
|---|---|---|
| 总后台（管理端） | 平台管理员 | 最高权限：管理所有商家账号、格位、积分、训练权限、素材、全局数据 |
| 分后台（客户端） | 入驻商家/品牌 | 上架自家服饰、看自家数据、账号设置 |
| 设备前台 | 门店顾客 | 分类选衣、实时试穿、扫码核销、待机广告、互动玩法 |

## 2. 角色与权限

- 管理端与客户端功能基本一致，管理端仅多出“调度监管 + 最高权限”。
- 品牌名称、Logo 由平台统一设定，客户端只读。

## 3. 需求清单

优先级：P0 = 首个可交付版本必须；P1 = 第二批；P2 = 可后置。

### 3.1 账号（ACC）

| 编号 | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| ACC-01 | 总后台登录页：管理员账号 + 登录口令 | P0 | 口令错误不可进入；连续失败有限流 |
| ACC-02 | 分后台注册页 + 用户名密码登录 | P0 | 注册后可登录；密码加盐哈希存储 |
| ACC-03 | 登录页背景图可替换（产品后续提供） | P0 | 替换图片无需改代码 |
| ACC-04 | 平台品牌名 + Logo（需设计），两端展示；客户端不可修改 | P0 | 客户端无修改入口，接口拒绝修改 |
| ACC-05 | 管理端管理商家账号：列表、启用/停用、重置密码、查看数据 | P0 | 停用后该账号无法登录，其服饰不在设备展示 |

### 3.2 客户端设置（SET）

| 编号 | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| SET-01 | 修改昵称、修改密码 | P0 | 改密后旧会话失效 |
| SET-02 | 积分剩余、积分充值 | P0 | 余额与流水一致（充值方式待确认 Q3） |
| SET-03 | 账号使用总时长 | P0 | 按试穿会话累计（口径待确认 Q9） |
| SET-04 | 设备黑白背景切换 | P1 | 设置后设备前台背景随之切换 |
| SET-05 | 服饰训练按钮：客户端点击提示“你的账户没有权限，请联系管理员” | P0 | 文案一致；管理端有该权限 |
| SET-06 | 联系我们 | P1 | 展示平台联系方式（内容待提供） |
| SET-07 | 用户留言反馈，管理端汇总查看 | P1 | 留言在管理端可见、可标记已处理 |
| SET-08 | 打赏作者 | P2 | 展示收款码（形式待确认 Q10） |

### 3.3 服饰上架（GAR）

| 编号 | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| GAR-01 | 每个新账号默认 18 个服饰格，格内客户端自行上传 | P0 | 第 19 次上传被拒 |
| GAR-02 | 格位用完点“+”提示“请联系管理员” | P0 | 文案一致 |
| GAR-03 | 管理端为指定账号加格，每次 +5 | P0 | 加格后客户端格数即时 +5，留操作日志 |
| GAR-04 | 上传后显示倒计时，下方小字：“上传服饰需要等待1-2小时的训练周期，所用时长视情况而定，最长不超过2小时。” | P0 | 文案一致 |
| GAR-05 | 上传成功但设备不立即可用，平均约 1 小时后可用，最长 2 小时 | P0 | 到达可用时间前设备不展示；超时 2 小时必可用（实现方式待确认 Q6） |
| GAR-06 | 服饰属性：所属品牌、性别（男/女/童）、品类、套装/单品、当季热卖、店铺位置 | P0 | 设备前台能按这些属性筛选 |

### 3.4 设备前台（DEV）

| 编号 | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| DEV-01 | 一级模块：流行男装、流行女装、童装、热门榜、宴会时装、热播短剧同款、运势穿搭、星座轮盘、AI智趣推荐、广告短剧热门 | P0 | 10 个入口均可进入 |
| DEV-02 | 二级：男/女/童下分“当季热卖套装”“上装单品” | P0 | — |
| DEV-03 | 三级：品牌 → 品类（连衣裙、T恤、衬衫、外套、风衣、针织衫、西装、羽绒服） | P0 | 空品类不显示或显示空态 |
| DEV-04 | 点击服饰即实时试穿（沿用 Xmax 实时换装） | P0 | 换衣不断流 |
| DEV-05 | 试穿时左下/右下角显示店铺位置 + 核销二维码 | P0 | 不遮挡试穿主体与结束按钮 |
| DEV-06 | 微信扫码 → 打开该次试穿的固定快照页，快照上带店铺核销码 | P0 | 快照稳定可重复打开；码与该次试穿唯一对应 |
| DEV-07 | 店员核销，核销后计入统计 | P0 | 同一码不能重复核销（核销入口待确认 Q5） |
| DEV-08 | 广告短剧热门：播放后台上传的 MP4 等视频，多个视频轮播 | P1 | 播放列表在后台可排序 |
| DEV-09 | 无人操作 4 分钟自动进入视频播放；触屏返回选衣界面 | P0 | 试穿中不触发待机（试穿中是否计时待确认 Q11） |
| DEV-10 | 支持幻灯片（图片轮播） | P1 | 与视频可混排 |
| DEV-11 | 星座轮盘：选十二星座 → 选男/女/童 → 转盘；转动需物理惯性与自然减速 | P1 | 转盘结果落到具体服饰 |
| DEV-12 | 运势穿搭：由开发方设计玩法 | P1 | 方案见业务设计，产品确认后开发 |
| DEV-13 | AI智趣推荐：选性别 + 场景（约会局、闺蜜局等）→ 推荐；同一人同一问题不出现同一套衣服 | P1 | “同一人”识别口径待确认 Q4 |
| DEV-14 | 热门榜：按试穿次数排名 | P1 | 统计口径与 STA 一致 |

## 4. 非功能要求

- 设备前台运行在广告机外壳（Electron）内，触摸优先：交互用 pointer 事件，不依赖 click/hover。
- 公开仓库：任何密钥、服务器地址、口令不入库，全部环境变量注入。
- Xmax 永久密钥只在服务端，设备只拿短期临时密钥。

## 5. 不做（V1.0）

- 人脸识别、顾客注册登录。
- 自建 AI 模型训练（“训练周期”为业务流程，不代表需要训练模型，见 Q6）。
- 复刻原厂“幻衣魔镜”后台接口。
