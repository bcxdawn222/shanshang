# 部署手册

> 文档用途：首次部署、更新、回滚、备份恢复、HTTPS 与上线前检查的操作步骤
> 当前状态：待验证（脚本与配置已写，未在服务器上实操）
> 最后更新时间：2026-10-31
> 对应需求：Phase 8 上线；PLY-04（断网续播）、RDM-02（微信打开快照页）

本仓库公开：下文 `<DOMAIN>`、`<USER>@<SERVER>` 均为占位符，真实地址、账号、密钥只在私有渠道和服务器 env 文件里。拓扑与环境变量说明见[服务器与部署](<服务器与部署.md>)。

## 1. 文件与目录

| 仓库文件 | 用途 |
|---|---|
| `deploy/nginx/shanshang.conf` | 加进现有 server 块的 `/sl/` location 片段 |
| `deploy/systemd/shanshang.service` | systemd unit |
| `deploy/server.env.example` | 服务器 env 模板 |
| `deploy/scripts/build.sh` | 本地构建 admin/device 并打包到 `deploy/out/` |
| `deploy/scripts/deploy.sh` | 上传、安装依赖、备份、切换、重启、健康检查；`--rollback` 回滚 |
| `deploy/scripts/backup-db.sh` | SQLite 在线备份，保留 14 天 |

| 服务器路径 | 内容 | 属主 / 权限 |
|---|---|---|
| `/opt/shanshang/releases/<版本>/` | 每次发布一个目录：`server/ admin/ device/ scripts/ VERSION` | root，755 |
| `/opt/shanshang/current` | 软链，指向当前版本 | root |
| `/etc/shanshang/server.env` | 环境变量（含 Xmax 永久密钥） | root，600 |
| `/var/lib/shanshang/` | `shanshang.db`（WAL）+ `media/` | shanshang，750 |
| `/var/backups/shanshang/` | 数据库备份 | shanshang，700 |

## 2. 首次部署

服务器（root）：

1. 安装 Node 20.6+（系统包或 NodeSource，装到 `/usr/bin/node`；不要用 nvm，服务用户读不到 `/root`）、nginx、curl；可选 `sqlite3`。better-sqlite3 没有预编译包时还需 `build-essential python3`。
2. 建用户和目录：
   ```bash
   useradd --system --home-dir /var/lib/shanshang --shell /usr/sbin/nologin shanshang
   install -d -m 750 -o shanshang -g shanshang /var/lib/shanshang
   install -d -m 700 -o shanshang -g shanshang /var/backups/shanshang
   install -d -m 755 /opt/shanshang/releases
   install -d -m 750 /etc/shanshang
   ```
3. 上传 `deploy/server.env.example` 为 `/etc/shanshang/server.env`，`chmod 600`，填写 `PUBLIC_BASE_URL`、`ADMIN_USERNAME`/`ADMIN_PASSWORD`（≥12 位）、`XMAX_API_KEY`/`XMAX_API_BASE`。还没上 HTTPS 时 `COOKIE_SECURE=0`，否则登录不上。
4. 安装 unit：`install -m 644 shanshang.service /etc/systemd/system/ && systemctl daemon-reload && systemctl enable shanshang`（先不 start，没有代码）。

本地：

5. `bash deploy/scripts/build.sh`（工作区需已提交；产物 `deploy/out/shanshang-<版本>.tar.gz`）。
6. `DEPLOY_HOST=<USER>@<SERVER> bash deploy/scripts/deploy.sh`（首次没有上一版本，健康检查失败不会回切，直接看 `journalctl -u shanshang`）。

服务器：

7. 把 `deploy/nginx/shanshang.conf` 的 location 粘进现有 server 块；**不改 `/mc/` 和 server 块其它内容**。`nginx -t && systemctl reload nginx`。
8. 验证：`curl -fsS http://127.0.0.1:8300/api/health`；浏览器打开 `https://<DOMAIN>/sl/admin/` 用超级管理员登录。
9. 登录成功后清空 env 里的 `ADMIN_PASSWORD` 并 `systemctl restart shanshang`。
10. 配置定时备份：`crontab -u shanshang -e`，加入 `backup-db.sh` 头部注释里的那一行。

## 3. 更新

```bash
bash deploy/scripts/build.sh
DEPLOY_HOST=<USER>@<SERVER> bash deploy/scripts/deploy.sh
```

脚本会在切换前自动备份数据库；新版本健康检查（`/api/health`，30 秒）失败会自动切回上一版本。数据库迁移在服务启动时自动执行（`migrations/*.sql`，只增不回退）。只保留最近 5 个版本（`KEEP_RELEASES`）。

## 4. 回滚

- 代码：`DEPLOY_HOST=<USER>@<SERVER> bash deploy/scripts/deploy.sh --rollback`（上一版本），或 `--rollback <版本>`。只切 `current` 软链并重启。
- 新版本执行过迁移、旧代码不兼容新表结构时，同时按 §5 恢复发布前的数据库备份（备份之后的业务数据会丢失，先确认）。

## 5. 备份与恢复

- 数据库：`backup-db.sh` 每天在线备份到 `/var/backups/shanshang/shanshang-<时间>.db.gz`，做 `integrity_check`，保留 14 天；发布时额外备份一次。
- 媒体：`/var/lib/shanshang/media/`（服饰图、广告视频、快照图）不在脚本里，用 `rsync -a` 定期同步到另一台机器或对象存储。
- 备份要异机保存：至少每周把 `/var/backups/shanshang/` 拉到服务器以外。

恢复：

```bash
systemctl stop shanshang
cd /var/lib/shanshang
mv shanshang.db shanshang.db.broken-$(date +%s)
rm -f shanshang.db-wal shanshang.db-shm
gunzip -c /var/backups/shanshang/shanshang-<时间>.db.gz > shanshang.db
chown shanshang:shanshang shanshang.db && chmod 640 shanshang.db
systemctl start shanshang
```

## 6. HTTPS

必须 HTTPS + 备案域名：

- 设备前台的 Cache Storage（广告素材断网续播，PLY-04）只在安全上下文可用，HTTP 下 `caches` 不存在，断网就黑屏。
- 微信内打开快照页（RDM-02）需要备案域名，未备案或 HTTP 会被拦截或提示风险。
- 会话 Cookie 需 `COOKIE_SECURE=1`，只在 HTTPS 下发送。

步骤：备案完成 → 域名解析到服务器 → 用 certbot（或云厂商证书）为现有 server 块签发证书 → 确认 `/mc/` 仍正常 → 改 `COOKIE_SECURE=1`、`PUBLIC_BASE_URL=https://<DOMAIN>/sl` → 重启服务。HSTS 影响整个域名（含 `/mc/`），由站点负责人确认后在 server 块统一加。

生产迁独立服务器、去掉 `/sl` 前缀时：`build.sh` 设 `ADMIN_BASE=/admin/ DEVICE_BASE=/device/`，nginx 片段把 `/sl/` 全部替换掉，`PUBLIC_BASE_URL` 去掉 `/sl`。

## 7. 上线前检查清单

- [ ] 产品方已更换服务器 root 密码（旧密码曾泄露）；ssh 改为密钥登录。
- [ ] 已在 Xmax 平台重建永久密钥，旧密钥作废；新密钥只在 `/etc/shanshang/server.env`（600，root）。
- [ ] `TRUST_PROXY=1`（否则所有人共享 127.0.0.1 的登录限流）。
- [ ] HTTPS 生效，`COOKIE_SECURE=1`，`PUBLIC_BASE_URL` 为 https 地址。
- [ ] env 里 `ADMIN_PASSWORD` 已清空；超级管理员口令不是演示口令。
- [ ] 演示商家已停用（Phase 8 计划）。
- [ ] `/api/health` 返回 `xmaxKeyConfigured: true`。
- [ ] 上传一个接近 200MB 的视频成功；广告机拖动 / 播放视频正常（Range 206）。
- [ ] 广告机断网后待机视频继续播放。
- [ ] 微信扫快照二维码能打开并长按保存；商家核销链接可用。
- [ ] `/mc/` 原有系统访问正常。
- [ ] 定时备份已生效，并做过一次恢复演练和一次回滚演练。
- [ ] 仓库里没有 `.env`、数据库、`deploy/out/`（`git status` 确认）。
