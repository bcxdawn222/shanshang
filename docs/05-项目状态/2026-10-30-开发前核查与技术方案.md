## 3. 技术选型

| 部分 | 选型 | 理由 |
|---|---|---|
| 服务端 | Node 20 + Fastify + better-sqlite3 | 与现有后端同栈；单机小内存可跑；SQLite 免运维 |
| 后台前端 | Vue 3 + Vite + Element Plus（以 vue-pure-admin 精简版起步） | 管理端与商家端同一 SPA，按角色出菜单 |
| 设备前台 | Vite + 原生 JS（沿用现有试穿页） | 广告机性能有限，轻量；已有触摸修复经验 |
| 快照页 | 服务端直出 HTML | 微信内打开快、无需构建 |
| 测试 | Vitest（前端）+ node:test（服务端） | — |

目录：

```
apps/
├── server/   API、鉴权、上传、积分、统计汇总、快照页
├── admin/    总后台 + 分后台
└── device/   设备前台
docs/
```

## 4. 数据表（初版）

| 表 | 用途 |
|---|---|
| `user` | 管理员与商家：角色、用户名、密码哈希、昵称、状态（待审核/正常/停用） |
| `merchant` | 商家 = 品牌：品牌名、店铺位置、格位配额、积分余额快照 |
| `point_ledger` | 积分流水（只追加）：充值、调整、试穿消耗 |
| `garment` | 服饰：商家、图片、Xmax URL、性别、类型、品类、主色、场景标签、折扣文字、状态、available_at |
| `category` / `tag` / `color` | 品类、场景标签、主色字典 |
| `device` | 设备：设备码、名称、地点、背景色、状态、最后心跳 |
| `tryon_segment` | 试穿分段：设备、会话、服饰、商家、起止时间（扣费与时长统计的依据） |
| `media` / `playlist_item` | 视频/图片素材、播放顺序、停留秒数、投放设备 |
| `topic` / `topic_garment` | 短剧专题与同款服饰 |
| `hot_override` | 热门榜置顶/移出 |
| `snapshot` | 快照：token、6 位核销短码、服饰、图片、状态、过期时间 |
| `event` / `stat_daily` | 埋点明细与日汇总 |
| `fortune_text` / `zodiac_map` / `recommend_option` | 运势文案库、星座映射、推荐选项 |
| `feedback` | 留言与回复 |
| `audit_log` | 后台操作审计 |
| `setting` | 平台名、Logo、登录背景、联系方式、收款码、积分比例与阈值等 |

## 6. 风险

| 风险 | 应对 |
|---|---|
| 备案域名未到位，微信扫码打不开 | 核销后台部分先完成；域名到位前用手机浏览器验收 |
| 测试服务器内存 1.8G 且与他人共用 | 开发期只新增 `/sl/` location；上线迁独立服务器 |
| 快照含顾客人像 | 扫码前提示、随机令牌、noindex、7 天删除 |
| Xmax 成本随试穿时长线性增长 | 4 分钟无操作结束试穿、单次 5 分钟上限、余额阈值隐藏 |
| 泄露的服务器密码与 Xmax 永久密钥 | Phase 1 部署前由产品方更换 |
