## 1. PRD 核对结论

| 结论 | 说明 |
|---|---|
| 需求可落地 | 44 条需求均可实现，无技术阻断 |
| 存在口径缺口 | 12 项需产品确认，见[待产品确认问题](<2026-10-30-待产品确认问题.md>)；其中 Q2、Q3、Q5、Q7 影响数据模型或上线，需优先答复 |

## 2. 现有基础（可复用）

| 已有 | 复用方式 |
|---|---|
| 单机 Xmax 试穿页（Vite + `@xmaxai/sdk`，触摸适配） | 改造为设备前台的试穿模块 |
| 极简 Node 后端（临时密钥签发、服装清单） | 签发逻辑并入新服务端 |
| 广告机双应用外壳（Electron） | 设备前台作为其中一个应用加载，外壳不改 |

以上代码在原工作目录，按需迁入本仓库 `apps/`，迁入时清除所有硬编码地址与密钥。

## 3. 技术选型

| 部分 | 选型 | 理由 |
|---|---|---|
| 服务端 | Node 20 + Fastify + better-sqlite3 | 与现有后端同栈；单机小内存可跑；SQLite 免运维 |
| 后台前端 | Vue 3 + Vite + Element Plus | 管理端与商家端同一 SPA，按角色出菜单 |
| 设备前台 | Vite + 原生 JS（沿用现有试穿页） | 广告机性能有限，轻量；已有触摸修复经验 |
| 快照页 | 服务端直出 HTML | 微信内打开快、无需构建 |
| 测试 | Vitest（前端）+ node:test（服务端） | — |

目录：

```
apps/
├── server/   API、鉴权、上传、统计汇总、快照页
├── admin/    总后台 + 分后台
└── device/   设备前台
docs/
```

## 4. 数据表（初版）

| 表 | 用途 |
|---|---|
| `user` | 管理员与商家：角色、用户名、密码哈希、昵称、状态 |
| `merchant` | 商家资料：品牌名、店铺位置、格位配额、积分余额快照、背景色 |
| `point_ledger` | 积分流水 |
| `garment` | 服饰：商家、图片、Xmax URL、性别、品类、套装/单品、标签、状态、available_at |
| `device` | 设备：设备码、名称、绑定商家（Q2）、最后在线 |
| `media` | 视频/图片素材与播放顺序 |
| `snapshot` | 试穿快照：token、核销短码、服饰、图片、状态、过期时间 |
| `event` / `stat_daily` | 埋点明细与日汇总 |
| `feedback` | 留言反馈 |
| `audit_log` | 后台操作审计 |
| `setting` | 平台品牌名、Logo、登录背景、联系方式等 |

## 6. 风险

| 风险 | 应对 |
|---|---|
| 无备案域名，微信扫码打不开 | P0 先完成核销闭环的后台部分；域名到位前用手机浏览器验收 |
| 服务器内存 1.8G 且与他人共用 | SQLite + 单进程；上传图片压缩；若商家多再迁独立服务器（Q8） |
| 设备截图含顾客人像 | token 访问 + 过期删除 + noindex |
| Xmax 成本随试穿时长线性增长 | 待机自动结束试穿；积分不足拦截 |
